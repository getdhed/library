# Руководство пользователя системы «Электронная Библиотека»

Данное руководство описывает доступный функционал и сценарии использования системы для двух основных ролей: **Обычного пользователя** и **Библиотекаря**. Функционал Супер-администратора (включая поддержку и деплой) будет описан в отдельном документе.

---

## 1. Обычный пользователь (Читатель)

Обычный пользователь имеет доступ к публичной части библиотеки. Его главная цель — поиск, чтение и сохранение интересующих его материалов, а также возможность предлагать новые документы для добавления в библиотеку.

### Основные возможности:

*   **Регистрация и Авторизация**
    *   Создание личного аккаунта (ФИО, логин, пароль).
    *   Вход в систему для получения доступа к защищенным материалам и персональным функциям.
*   **Поиск и навигация по каталогу**
    *   Просмотр каталога всех доступных документов.
    *   Поиск по ключевым словам (название, автор).
    *   Умные подсказки (саджесты) при вводе запроса в строку поиска.
    *   Фильтрация материалов по типу (Книга, Статья, Учебник, Журнал и т.д.), году издания, тегам.
    *   Просмотр детальной карточки документа (аннотация, авторы, год, количество страниц, размер файла).
*   **Чтение документов**
    *   Встроенный PDF-ридер для комфортного чтения прямо в браузере без необходимости скачивания.
    *   Скачивание исходного файла документа (если разрешено).
*   **Персонализация (Личный кабинет)**
    *   **Избранное**: добавление документов в закладки для быстрого доступа в будущем (раздел "Мое избранное").
    *   **История просмотров**: отслеживание недавно открытых и прочитанных документов.
    *   **История поиска**: сохранение последних поисковых запросов для быстрого повторения поиска.
*   **Предложение материалов (Заявки)**
    *   Если пользователь не нашел нужный документ, он может загрузить свой PDF-файл и заполнить базовые данные (Название, Авторы, Описание).
    *   Отправка заявки на модерацию библиотекарю.
    *   Отслеживание статуса своих заявок в Личном кабинете (В ожидании, Одобрено, Отклонено).

## 2. Библиотекарь (Администратор контента)

Библиотекарь имеет полный доступ к функционалу Обычного пользователя, а также доступ к **Панели Администратора**. Его главная цель — управление фондом библиотеки, модерация контента и контроль за пользователями.

### Разделы и возможности Панели Администратора:

#### 2.1. Модерация заявок
*   Просмотр списка всех предложенных пользователями документов.
*   Проверка загруженного пользователем PDF-файла и введенных метаданных.
*   **Одобрение заявки**: при одобрении библиотекарь может отредактировать метаданные (например, исправить опечатки, добавить теги), после чего документ официально публикуется в общем каталоге.
*   **Отклонение заявки**: отклонение загруженного материала (например, если это спам, дубликат или неподходящий формат) с возможностью указания причины (если предусмотрено системой).

#### 2.2. Управление документами (Каталог)
*   **Добавление новых документов**: прямая загрузка PDF-файлов, генерация обложек, заполнение всех полей (Название, Авторы, Год, Тип, Теги).
*   **Редактирование**: изменение карточки любого существующего документа в базе.
*   **Удаление (Soft Delete)**: перемещение документа в «Архив». Документ скрывается из общего каталога, но физически остается в базе данных для возможности восстановления.

#### 2.3. Управление пользователями
*   Просмотр полного списка зарегистрированных читателей.
*   Поиск пользователей по логину или ФИО.
*   **Блокировка / Разблокировка**: изменение статуса аккаунта пользователя (например, временная блокировка за нарушение правил библиотеки). Заблокированный пользователь не может авторизоваться в системе.
*   **Редактирование профилей**: изменение данных пользователей (ФИО, логин) или сброс/установка нового пароля по их запросу.
*   Создание новых пользователей вручную через админку.

#### 2.4. Статистика
*   Просмотр графиков активности (количество посещений, загрузок, просмотров документов за разные периоды: день, неделя, месяц).
*   Аналитика популярности материалов.

#### 2.5. Журнал действий (Аудит)
*   Просмотр подробного лога всех значимых действий в системе (кто, когда и что сделал).
*   Отслеживание изменений в документах (какие поля были изменены, кто одобрил заявку, кто удалил файл).
*   Удобный инструмент для разбора конфликтных ситуаций или ошибок контент-менеджмента.

#### 2.6. Архив
*   Просмотр списка всех удаленных (Soft Delete) документов и заблокированных/удаленных пользователей.
*   **Восстановление**: возврат документа в публичный каталог или восстановление аккаунта пользователя.
*   *(Примечание: Полное физическое удаление (Hard Delete) обычно недоступно библиотекарю во избежание случайной потери данных и является прерогативой Супер-администратора).*

## 3. Супер-администратор (Super Admin) и DevOps

Супер-администратор (superadmin) — это высший уровень доступа в системе. В интерфейсе он может делать всё то же, что и библиотекарь, плюс обладает правом на необратимое удаление данных. Но главная задача Супер-администратора — это **развертывание (деплой) проекта на сервере** и его **обслуживание (maintenance)**.

---

### ЧАСТЬ 1: Системные функции в интерфейсе (Админ-панель)

#### 1. Необратимое удаление данных (Hard Delete)
Обычный библиотекарь может только отправлять книги в Архив (Мягкое удаление / Soft Delete).
Супер-администратор имеет право нажать кнопку **"Удалить навсегда"**:
*   Это полностью стирает строку из базы данных PostgreSQL.
*   Это физически удаляет PDF-файл книги и её обложку с жесткого диска сервера, безвозвратно освобождая место.
*   Используйте эту функцию только при 100% уверенности, что данные больше не нужны.

#### 2. Резервное копирование (Скачивание БД из браузера)
*   В разделе **"Статистика"** внизу страницы вы увидите блок "Системные действия".
*   При нажатии на **"Скачать базу данных"**, система автоматически выполнит системную команду внутри сервера и отдаст вам готовый файл `library_backup.bak`.
*   Сохраняйте этот файл в надежное место. Рекомендуется делать это регулярно (например, раз в неделю).

### ЧАСТЬ 2: Пошаговое руководство по Деплою на новый сервер

Проект работает внутри изолированных контейнеров **Docker**. Это значит, что вам не нужно устанавливать язык программирования Go, Python или Node.js на сам Windows/Linux сервер. Нужен только Docker Desktop (для Windows) или Docker Engine (для Linux).

#### Шаг 1. Подготовка файлов проекта
Вам понадобятся файлы репозитория. Самое главное, что должно оказаться на сервере в рабочей папке (например, `C:\LibraryApp` на Windows Server или `/opt/library` на Linux):
1. Файл конфигурации инфраструктуры `docker-compose.yml`.
2. Папки `backend/` и `frontend/` с их исходным кодом и файлами `Dockerfile`.
3. Важно создать пустую структуру папок для физического хранения файлов (Storage). В корне проекта:
   *   Создайте папку `backend`
   *   Внутри нее папку `storage`
   *   Внутри `storage` создайте три пустые папки: `pdfs`, `covers` и `import`.

*(Примечание: Если сервер является закрытым контуром без доступа к интернету, вы должны заранее собрать образы на компьютере разработчика, сохранить их через команду `docker save -o library.tar library-backend library-frontend`, перенести этот `.tar` на сервер через флешку и загрузить через `docker load -i library.tar`)*.

#### Шаг 2. Создание файла настроек (.env)
В корневой папке проекта (там же, где лежит `docker-compose.yml`) создайте текстовый файл и назовите его строго `.env` (без имени до точки, только расширение).
Откройте его в блокноте и скопируйте туда следующий текст, обязательно заменив пароли на свои собственные:

```env
# ==== БАЗА ДАННЫХ ====
POSTGRES_USER=library
# Придумайте сложный пароль для базы данных (без спецсимволов вроде @ и :, чтобы не сломать URL)
POSTGRES_PASSWORD=MySuperSecretPassword123
POSTGRES_DB=postgres

# ==== БЭКЕНД ====
# Вставьте сюда ровно тот же пароль, что и строчкой выше
DATABASE_URL=postgres://library:MySuperSecretPassword123@db:5432/postgres?sslmode=disable
# Придумайте случайную длинную строку для шифрования сессий (можно просто потыкать по клавиатуре)
JWT_SECRET=asd8f7gwq487gf23478fy23g847gf238
# Укажите адрес, по которому будет доступен ваш фронтенд
CORS_ORIGINS=http://localhost:5173,http://your-server-ip.com
# Максимальный размер загружаемого PDF файла в Мегабайтах
MAX_UPLOAD_SIZE_MB=50

# ==== ФРОНТЕНД ====
# Адрес, по которому фронтенд будет стучаться к бэкенду. Оставьте /api
VITE_API_URL=/api
```
Сохраните и закройте файл.

#### Шаг 3. Запуск проекта
Откройте терминал (PowerShell от имени Администратора в Windows или bash в Linux) и перейдите в папку вашего проекта:
```bash
cd C:\LibraryApp  # Пример для Windows
# или
cd /opt/library   # Пример для Linux
```

Выполните одну магическую команду сборки и запуска:
```bash
docker compose up --build -d
```
**Что произойдет под капотом:**
1. Docker скачает нужные операционные системы для контейнеров (Alpine Linux).
2. Скомпилирует код бэкенда (Go) и фронтенда (React).
3. Запустит базу данных и применит её структуру таблиц.
4. Запустит систему в фоновом режиме (за это отвечает ключ `-d`).

#### Шаг 4. Проверка и первый вход
*   Сайт (фронтенд) будет доступен в браузере на порту `5173` (например, `http://localhost:5173`).
*   Серверная часть (бэкенд) работает на порту `8080`.
*   По умолчанию база пустая. Вам необходимо нажать "Регистрация" на сайте и создать первого пользователя. В дальнейшем статус `superadmin` этому пользователю можно будет выдать через прямое изменение в базе данных (или заложив этот механизм в скрипты миграции).

### ЧАСТЬ 3: Обслуживание проекта и Решение проблем (Сценарии)

#### Сценарий 1: Проект завис или нужно применить новые настройки из `.env`
Если вы изменили файл `.env` (например, обновили пароль) или проект начал вести себя странно, контейнеры нужно перезагрузить.
Выполните в терминале в папке проекта:
```bash
# Эта команда остановит все запущенные контейнеры
docker compose down

# Эта команда запустит их заново с новыми настройками
docker compose up -d
```

#### Сценарий 2: Выпущена новая версия (Апдейт проекта)
Обновление проекта зависит от того, как вам передали новую версию: исходными кодами или готовыми `.tar` архивами (для серверов без интернета).

**Вариант А. Обновление исходным кодом (стандартный сценарий)**
1. Замените старые файлы кода в вашей папке на сервере на новые. **Внимание:** папку `backend/storage` трогать нельзя, иначе удалятся книги!
2. Если нужно обновить **только Бэкенд**:
   ```bash
   docker compose up --build -d backend
   ```
3. Если нужно обновить **только Фронтенд**:
   ```bash
   docker compose up --build -d frontend
   ```
4. Если нужно обновить **весь проект целиком**:
   ```bash
   docker compose up --build -d
   ```
Докер пересоберет только то, что изменилось. Контейнер базы данных (`db`) при этом не затронется, поэтому ваши пользователи и книги в безопасности.

**Вариант Б. Обновление через `.tar` образы (offline-деплой для закрытых серверов)**
Если вам принесли обновления в виде архивов (например, `library-backend.tar` и `library-frontend.tar`), ваши шаги следующие:
1. Загрузите файлы `.tar` на сервер в папку проекта.
2. Загрузите образы в Docker:
   ```bash
   docker load -i library-backend.tar
   docker load -i library-frontend.tar
   ```
3. (Опционально) Если вам передали новый файл `docker-compose.prod.yml` или `docker-compose.yml`, замените им старый.
4. Выполните команду пересоздания контейнеров. Докер увидит новые загруженные образы и перезапустит только их. Флаг `--no-deps` указывает докеру не трогать связанные контейнеры (т.е. база данных не уйдет в рестарт):
   ```bash
   # Если обновляем только бэкенд:
   docker compose up -d --no-deps backend
   
   # Если обновляем и бэкенд, и фронтенд:
   docker compose up -d --no-deps backend frontend
   ```

#### Сценарий 3: Как полностью восстановить базу данных из скачанного файла `.bak`
Предположим, вы скачали бекап через админку, а на следующий день кто-то случайно стер полбазы. Как вернуть всё как было?

1. Положите ваш скачанный файл `library_backup.bak` прямо в папку проекта.
2. Проверьте, что проект запущен. База данных обычно крутится в контейнере под названием `library-db-1`.
3. Скопируйте файл с жесткого диска прямо внутрь виртуального контейнера БД:
   ```bash
   docker cp ./library_backup.bak library-db-1:/tmp/library_backup.bak
   ```
4. Выполните команду восстановления (она сотрет сломанные данные и зальет чистые из бекапа):
   ```bash
   docker exec -it library-db-1 pg_restore -U library -d postgres --clean /tmp/library_backup.bak
   ```
5. Вы увидите логи процесса в терминале. Если нет фатальных красных ошибок (warnings можно проигнорировать) — восстановление прошло успешно! Зайдите на сайт и проверьте.
6. В конце удалите временный файл из контейнера, чтобы он не занимал место:
   ```bash
   docker exec -it library-db-1 rm /tmp/library_backup.bak
   ```

#### Сценарий 4: Резервное копирование ФАЙЛОВ (Storage)
База данных (`.bak`) хранит только *текст*: названия книг, их авторов, пароли пользователей. Сами **тяжелые PDF-файлы** и обложки лежат в физической папке `backend/storage`.
*   Если диск сервера сгорит, вам будет недостаточно одного только `.bak` файла базы данных! Книги восстановить не получится.
*   Поэтому вы должны регулярно архивировать папку `backend/storage` целиком (например, отправляя её в облако или на внешний диск).
*   **Для восстановления файлов:** просто скопируйте вашу сохраненную папку `storage` обратно на сервер по пути `backend/storage`, перезапустите докер (`docker compose restart`), и все файлы снова подтянутся на сайт.
